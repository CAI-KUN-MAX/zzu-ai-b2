## 一、环境准备

### 后端

- 线上地址：`https://8.163.105.39`（Nginx 同源 `/api`，HTTPS 自签证书）
- 岗位目录版本：`2026-10-28.v3`，可投岗位 **41** 条

### 前端（本地联调）

```bash
cd frontend
# .env
VITE_USE_MOCK=false
VITE_API_BASE=            # 留空：走同源 /api，由 vite 代理转发
VITE_PROXY_TARGET=https://8.163.105.39
```

> ⚠️ **不要**把 `VITE_API_BASE` 直接填成 `https://8.163.105.39`。
> 浏览器走 HTTP/2 跨域时，`POST /api/interviews/{id}/answers` 会在预检通过后被拦
> （`net::ERR_FAILED`），表现为「点提交没反应」。走 vite 代理就没有这个问题。

```bash
npm run dev     # http://localhost:5173
```

## 五、已知问题（影响演示效果，非前端 bug）

### 1. 岗位库没有前端岗位

41 条可投岗位中，计算机类只有 4 条：后端工程师、AI 应用开发、AI 产品经理、前沿部署工程师 FDE。
**没有一条前端/Web 岗位**，其余 37 条分布在材料、化工、土木、生物、法学等专业。

后果：一份前端简历在真实目录里最高只有 53 分，5 个岗位全是「存在缺口」，演示观感偏差。

### 2. 基础分（stage1）系统性偏低

以 53 分的 FDE 岗位为例：

| 分项 | 分数 |
| --- | --- |
| 技能关键词匹配（权重 55%） | **7** |
| 文本相似度（权重 30%） | **4** |
| 学历匹配（权重 15%） | 100 |
| 基础分 | 20 |

而同一岗位 AI 诊断给出的「技能匹配」是 **80** 分。规则分与 AI 分差 10 倍以上，
最终总分被 35% 的基础分权重拖到 53（若按 AI 71 分本可更高）。

建议后端核查关键词表覆盖范围与 2-gram 相似度在「短简历 vs 长 JD」下的取值。

### 3. 材料岗 AI 分 0

模型给材料研发岗的四个维度全部 0 分（`overall_score=0`、`mode=llm`、耗时 9.7 秒），
判定「专业不对口」。属模型真实输出而非降级，但 0 分过于极端，排序时会显得突兀。
